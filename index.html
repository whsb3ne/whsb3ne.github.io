Projects and labs

Home SOC Lab

  • Wazuh
  • Sysmon
  • MITRE ATT&CK
  • VirtualBox
Problem
I wanted to see detection from the analyst's side: what an attack looks like in telemetry, and how alerts are triaged, instead of only reading about it.
Approach
Built an isolated VirtualBox network with a Wazuh manager on Ubuntu Server, a Windows 10 endpoint running Sysmon, and Kali Linux as the attacking machine. Ran test activity from Kali and investigated the results in the Wazuh dashboard.
Outcome
Phase 1 is complete. The first test raised a level 15 alert (executable dropped in a folder commonly used by malware) and a level 12 alert (PowerShell spawning PowerShell with a Base64-encoded command). I mapped these to T1059.001 and T1105. Next: Linux endpoint monitoring, repeatable attack simulations and IR playbooks.

Incident 2:14, a beginner CTF

  • CTF design
  • Log analysis
  • Web security
  • GitHub Actions
Problem
Students at GDG on Campus, Mount Kenya University needed a first CTF that took them from "what is a terminal?" to reading an authentication log in one evening.
Approach
Co-designed with Yvonne (@Moseti-suddo): a story around an unrecognised login at a fictional company, split into two chapters. Seven challenges cover Base64, Linux basics, auth-log timelines, then IDOR, exposed files and cookie tampering on a staging web portal. A CI script checks every challenge is still solvable without printing any flag.
Outcome
It now runs every week for GDG on Campus, with new chapters added as the story continues. The repository is public under MIT, with official write-ups for players.

Role-based access control system

  • PHP
  • MySQL
  • RBAC
  • Audit logging
Problem
Small organisations, clubs and teams need user accounts where people only see and do what their role allows, and where an admin can check who did what.
Approach
A PHP and MySQL web app with three roles: Admin, Editor and Viewer. Every protected page checks the session role before it loads. Passwords are hashed with password_hash(), queries use prepared statements, and password resets use random tokens that expire after an hour. Logins are recorded with IP address and time, and uploads, edits and deletions go to an audit log only admins can view.
Outcome
A working system with user management (promote, demote, deactivate), file uploads, login history, an admin dashboard and a one-step database setup script. I built it during my diploma at Chuka University in 2025.

Scholarax: role-based access control for a school system

  • RBAC
  • NestJS
  • PostgreSQL
  • Multi-tenant
Problem
A school management system holds grades, attendance, medical records and fee payments for several campuses. Owners, administrators, teachers, bursars, parents and students each need a different slice of that data, and no one should reach another campus.
Approach
I built the access layer of a NestJS, Prisma and PostgreSQL backend. Each campus gets six standard roles, and endpoints declare the roles they allow. The guard denies access whenever it can't confirm a role. Every check goes through one normalisation function, so an alias like "admin" or "staff" can't mean different things in different places. Teachers only reach the streams they're assigned to, parents only their own children, and campus scoping is applied to database queries. Sessions use HttpOnly cookies with CSRF tokens, and the live user and roles are re-checked on each request.
Outcome
Role checks sit on 28 API controllers. Regression tests cover role denial, expired tokens, disabled accounts, cross-campus token reuse and tenant isolation. I also wrote down the gaps that are still open, such as database row-level security not yet being the active boundary. The project is in active development, and the repository is private.
